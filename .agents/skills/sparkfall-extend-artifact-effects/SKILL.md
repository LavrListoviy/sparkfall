# Расширение эффектов артефактов Sparkfall

Работай в корне репозитория. Расширяй конкретную возможность конструктора; не вводи универсальный язык сценариев, исполняемый код в каталоге или отдельный движок предметов.

## Уточнить контракт расширения

1. Прочитай [правила проекта](../../../AGENTS.md), раздел AE01–AE06 в [SPEC.md](../../../docs/SPEC.md), [инструкцию редактора](../../../docs/ARTIFACT_EDITOR.md), [схему](../../../public/core/artifact-schema.js) и [исполнитель](../../../public/core/artifact-rules.js). Проверь, нельзя ли решить задачу существующими правилами. Если можно, используй [навык создания артефакта](../sparkfall-create-artifact/SKILL.md).
2. Сформулируй минимальное расширение и один реальный пример предмета. Для события укажи момент вызова и контекст; для условия — когда читается состояние; для эффекта — получателя, величину, сопротивления, пределы и порядок. Уточни судьбу эффекта при погибшей цели, гибели героя, запрете лечения и уже потраченном лимите.
3. До реализации запиши правила, состояния, ограничения и критерии приёмки в `docs/SPEC.md`; добавь требование в [TEST_PLAN.md](../../../docs/TEST_PLAN.md) и задачи в [TODO.md](../../../TODO.md). Новое игровое поведение согласуй, если текущий запрос ещё не задаёт достаточный контракт. Уже согласованный объём выполняй без разрешений на каждый файл. Для исправления ошибки сохрани согласованное поведение и начни с воспроизведения.
4. Отдельно реши совместимость. Снимок каталога сохраняет данные, но не старую реализацию интерпретатора. Не меняй смысл существующего эффекта для исторических реплеев молча. При необходимости определи версию правил и миграцию; обычное добавление предмета не требует автоматического повышения версии формата.

## Найти минимальный набор изменений

| Часть | Где смотреть | Когда менять |
| --- | --- | --- |
| Формат и ограничения | [artifact-schema.js](../../../public/core/artifact-schema.js) | Новое поле, вариант или диапазон; учесть обычную проверку, черновик и снимок |
| Выполнение правил | [artifact-rules.js](../../../public/core/artifact-rules.js) | Новое условие, цель или эффект |
| Момент события | [battle.js](../../../public/core/battle.js), [storm.js](../../../public/core/storm.js) | Новый момент запуска или взаимодействие со штормом |
| Частоты | [glyphs.js](../../../public/core/glyphs.js) | Только если требование затрагивает генерацию глифов |
| Конструктор и стенд | [editor.js](../../../tools/artifact-editor/editor.js), [index.html](../../../tools/artifact-editor/index.html), [artifact-sandbox.js](../../../public/core/artifact-sandbox.js) | Настройка нового примитива, значения по умолчанию, воспроизводимый сценарий |
| Видимые боевые события | [text.js](../../../public/presentation/text.js), [timeline.js](../../../public/presentation/timeline.js), [scene.js](../../../public/presentation/scene.js) | Новый тип события или изменение его показа; проследить RU/EN по импортам |
| Снимки и воспроизведение | [run.js](../../../public/core/run.js), [save.js](../../../public/core/save.js), [replay.js](../../../public/core/replay.js), [report.js](../../../public/report.js) | Изменяется формат или смысл сохранённых правил |
| Запись редактора | [editor-server.mjs](../../../scripts/editor-server.mjs) | Только если расширение действительно затрагивает API; сохранить фиксированный путь, Origin, ревизии и атомарность |

Это карта поиска, не список обязательных правок. Следуй текущим импортам и реализации. Старые примеры ручного добавления предметов в документации не заменяют нынешний каталог.

## Реализовать через TDD

1. Проверь существующие тесты и добавь минимальный сценарий в соответствующий набор. Получи содержательное падение: например, герой не получает ожидаемый эффект или схема отклоняет согласованный новый вариант. Ошибка импорта и синтаксиса не доказывает отсутствие поведения. Для бага сначала воспроизведи неверный результат через публичный редьюсер.
2. Реализуй минимальное поведение отдельно от DOM и браузерного хранения. Передавай каталог и случайность явно. Конструктор сейчас не расходует RNG и не вызывает себя рекурсивно; изменение этих правил требует отдельного контракта.
3. Сохрани семантику существующих правил: порядок получения предметов, затем порядок правил; контекст группы до базового эффекта; лимит тратится при совпадении условий; погибшая исходная цель не заменяется другой. Не изменяй выбранную цель лишь ради чтения условий. После гибели героя эффекты прекращаются.
4. Изменения боя проводи через события и снимки принятого в ядре формата, чтобы расчёт и показ совпадали. При новом типе события проверь журнал, анимацию и обе локали. Не маскируй отсутствие обработки интерфейсным текстом.
5. Сделай новую возможность доступной без кода в конструкторе: варианты полей, нейтральные значения скрытых параметров, валидация, черновик, импорт/экспорт и стенд должны понимать один формат. Не сохраняй незнакомые поля, которые игра затем игнорирует.
6. Не расширяй [legacy-artifacts.js](../../../public/core/legacy-artifacts.js): это исторические данные. Если новый специальный базовый блок требует расширения списка, отдели актуальный реестр от исторических определений в пределах согласованной задачи. Для обычного нового эффекта достаточно ветки ограниченного исполнителя и схемы.
7. После успешного теста проверь важные границы именно новой механики: отсутствие условия, повтор и сброс лимита, смерть цели, сопротивления/пределы, порядок соседних эффектов. Выбирай применимые случаи, а не декартово произведение всех параметров. Тестируй наблюдаемое поведение, не устройство веток реализации.

## Довести до приёмки

- Для ядра начни с `test/artifact-editor.test.js` и `test/artifacts.test.js`; для структуры — с `test/artifact-catalog.test.js`. По затронутой области добавь проверки сохранения, реплея, частот, представления или HTTP в существующие наборы. Тесты нового каталога должны передавать `artifactCatalog` явно, чтобы не попасть в исторические определения по умолчанию.
- Проверь два пути совместимости: сохранённый забег со снимком продолжает прежнее поведение после правки каталога; старый отчёт без снимка воспроизводится по историческим правилам. При изменении интерпретатора нужен тест на старое значение эффекта, а не только на наличие снимка.
- Запусти `npm.cmd test`. Если менялся контент, сначала выполни `npm.cmd run glossary`; затем `npm.cmd run glossary -- --check`. Если тест локального API блокирует окружение, решай ограничение запуска, не ослабляй проверку.
- В браузере запусти `npm.cmd run editor`: создай временный сценарий, выбери новый примитив, проверь результат на стенде, сохранение, повторное открытие и RU/EN. Для новой вёрстки проверь клавиатуру и узкий экран. Предпочитай временный сценарий в памяти/черновике; если проверка записывала файл, убери только свою тестовую запись, сохранив чужие правки и запрошенный контент.
- Обнови `docs/ARTIFACT_EDITOR.md` и затронутые документы. Отметь проверенное в TODO. Сообщи, какая комбинация стала возможна, где она настраивается, как повторить QA и что осталось непроверенным. Не включай публикацию и изменения истории Git в расширение эффекта.
